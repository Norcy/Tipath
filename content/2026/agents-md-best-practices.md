## AGENTS.md 是什么？

简单说，AGENTS.md 是写给 AI 的规则文件。Codex 开始任务时，会自动读取相关的 AGENTS.md，把里面的规则带入当前任务。

利用好它，你和 AI 的协作就会越来越顺畅。

你肯定遇到过：

- 同一个错误，AI 犯了很多次。
- 同一个要求，你强调了很多遍。

**每当 AI 重复犯错，就该想想：是不是应该把这条规则写进 AGENTS.md？**

## 维护原则

1. **从空白开始。** 不要预设一大堆规则，只会浪费上下文，还可能限制 AI 的自主性。
2. **重复犯错再考虑添加。** 第一次犯错，直接纠正；反复出现，才值得沉淀。
3. **区分规则和流程。** 行为约束放 AGENTS.md，重复执行的工作流程封装成 Skill。
4. **定期清理。** 模型能力会进步，过时的规则该删就删。

## 几个实际例子

| 遇到的问题 | 解决方式 |
|---|---|
| AI 一次提交大量代码，Diff 太大，难以 Code Review | AGENTS.md：如果 Diff 难以 Review，先拆成便于人工审查的小批次，优先保持逻辑等价 |
| AI 总是写英文注释 | AGENTS.md：代码注释使用中文 |
| AI 喜欢为边角情况堆砌防御性代码 | AGENTS.md：增加防御性逻辑前，评估必要性；不确定就先讨论 |
| AI 写的代码不够优雅、简洁 | 在 AGENTS.md 的 `## Code Review Rules` 中沉淀审查原则，供 `/review` 参考 |
| AI 完成任务后留下大量分支、worktree、临时代码 | 创建 `my-clean` Skill，在任务结束时执行清理 |

## 推荐目录结构

```text
~/
├── .codex/
│   └── AGENTS.md                 # 全局：个人习惯
│
└── projects/
    ├── my-project/
    │   ├── AGENTS.md             # 项目：技术栈、开发规范
    │   └── src/
    │       └── AGENTS.md         # 子目录：模块特殊规则
    │
    └── fork-or-team-project/
        ├── AGENTS.md             # 上游或团队规则
        └── AGENTS.override.md    # 个人规则，替换同级 AGENTS.md
```

### 1. 规则优先级

**全局 → 项目 → 子目录**，规则逐级叠加，越具体的规则优先级越高。

### 2. AGENTS.override.md

Codex 支持 `AGENTS.override.md`，适合 Fork 第三方仓库或参与团队项目时，保留自己的开发习惯。

**它会完全替换同目录的 AGENTS.md，而不是追加内容。** 上级目录的规则仍然有效。

### 3. 不想把个人规则提交到 Git？

两种方式：

**仅自己忽略（推荐）**

在项目根目录执行：

```bash
echo '/AGENTS.override.md' >> .git/info/exclude
```

仅忽略项目根目录的文件，不影响其他人，也不需要提交。

**团队统一忽略**

```bash
echo 'AGENTS.override.md' >> .gitignore
```

提交 `.gitignore` 后，团队都会忽略所有目录下的同名文件。

以上方式只对尚未被 Git 跟踪的文件生效。

## 最后

以上都不是金科玉律，也没有四海皆准的规则。

也许换个模型，或者明天模型升级，这些规则就不再需要了。

但这不重要。

**最重要的是，对效率保持极致的敏感。**

发现哪里不爽，就想办法解决。解决一个，再解决下一个。

不断把踩过的坑变成规则，把重复的操作变成 Skill。

这个循环持续下去，你和 AI 协作的效率就会越来越高，最终获得极致顺滑的体验。
